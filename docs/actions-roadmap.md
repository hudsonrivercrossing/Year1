# 动作扩充可行性与顺序建议

研究基线：本地 `v1.0.0` / `7534e3f`。以下主体记录实施前的研究判断；随后获准实施的更新见文末。用户目前要的是扩充预编排动作与组合，不接 AI、不增加分别用 Prompt 指挥角色的层级。以下难度为结合当前代码的工程判断，不是耗时承诺。

## 结论与建议顺序

这些设想都可行，而且可以继续使用现在的 Three.js + 标准零件结构。

建议先确认照片零件与头发/脸部外观，再做 **羞羞 → 脸颊亲亲 → 亲亲、害羞、拥抱的小组合**。Phase 2 先做 **桌子和电脑进场 → 工作 → 完整退场**，验证道具的进入、占位、使用和清理；再做种树。原因是桌子可以在动作结束时全部撤走，种下后若留树，就需要决定数量、摆放和后续漫步避障。

亲亲时由一人主动、另一人回应，是一个双人动作内部的固定编排，不意味着要开放单独指挥功能。所有这些行为都可以本地执行，不需要 AI、网络或新增大型软件。

## 代码与实际资产支持什么

证据来自 `src/main.ts` 的 `makeFigure`、`pose`、`updateCharacters`，以及 `scripts/build_blender.py`：

- 两条腿有独立髋轴，两只手臂有肩部旋转节点。头部和头发各是独立组，现有代码同步它们的左右转头。
- 网页中的手是手臂子节点，但没有保存成可直接引用的手腕控制器；Blender 导出层级已有 hand 空节点。新增握持点无需拆成第七个可拼装组件，也无需改变用户装配流程。
- 没有肘、膝、腰部骨骼或面部变形。头是固定印花；严格积木风格的害羞可通过姿态表达，真实嘴唇、弯肘、屈膝不是现成能力。
- 实际检查 `public/models/characters.glb` 的 JSON：`animations = 0`，`skins = 0`，主要是 Group/Empty + 刚体网格层级。网页实际加载零件 JSON，并用程序设置关节角度，不加载这个 GLB 的动画。
- `activity` 是一个全局状态，当前动作结束就回 wander；`pose()` 每帧先重设部分姿态。拥抱会走向固定的场地中心，而非在角色当前位置附近选互动点。根节点高度也在每帧末统一写回。

因此，增加几个温柔的积木姿态，不需要先做真人骨骼或 IK；但不能直接把新动作不断加进一个越来越长的 `if`，否则姿态、时序和退出条件容易互相覆盖。Three.js 的 Object3D 本身提供父子层级和变换，适合当前刚体关节模型；手持道具也可用同一层级表达。[Three.js r180 Object3D 官方源码](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js)

## Phase 1：情感动作与小组合

| 动作 | 建议表现 | 当前需要补的能力 | 相对难度 |
| --- | --- | --- | --- |
| 羞羞 | 偷看对方 → 微微低头/偏头 → 双手靠近脸颊或背到身后 → 小幅晃身 → 恢复 | 头和头发同步姿态；肩部动作包络；可恢复的身体倾斜 | 低至中 |
| 脸颊亲亲 | 靠近 → 一人转脸露出脸颊 → 对方轻靠近 → 短暂停留 → 分开 → 害羞回应 | 双人局部站位、朝向与头部接近点；发型/眼镜/饰物的间距检查 | 中 |
| 嘴对嘴亲亲 | 两人正面对齐 → 轻靠近 → 停留 → 分开 | 更精细的面部接触与身体间距，避免圆柱头、头发和鼻前配件互穿；从多视角仍需读得懂 | 中至高，建议后做 |
| 靠靠/依偎 | 并肩站 → 一人轻轻偏向肩边 → 停留 → 站正 | 安全的靠近距离、统一头部控制与轻微全身倾斜 | 中 |
| 开心一下/小庆祝 | 看对方 → 抬臂 → 小幅一起弹一下 → 恢复 | 复用舞蹈现有抬臂和整体高度偏移，做好落地过渡 | 低至中 |
| 击掌 | 面向对方 → 抬臂 → 两个夹手接近 → 分开 | 手部接近点和双人时序；C 形夹手没有手指，可用积木式碰手表达 | 中，不作为首项 |

脸颊亲亲优先的理由是工程与视觉上的判断：它允许错开两人的头部，接近、停留和害羞回应也更有可读性。最终是否好看仍需用选定发型、眼镜和手持配件，在旋转视角下实际预览，不能只保证数学上的接近。

不必为了羞羞立刻替换脸部印花。若以后要加红脸，可增加独立的浅色脸颊效果层；先用姿态表达能保留照片里选定的标准头部。

建议先做三条短组合：

- 亲亲 → 羞羞 → 拥抱 → 漫步。
- 打招呼 → 靠近 → 依偎 → 分开 → 漫步。
- 开心一下 → 一起跳舞 → 短暂停留 → 漫步。

组合复用同一动作定义，通过内部步骤执行；不要给每个组合复制一份动画代码，也不用把每个新动作都铺成首页按钮。

## Phase 2：道具小剧场

### 先做桌子与电脑

最小完整流程：选空位置和站位 → 道具整体从底板边缘推入 → 两人走到桌边 → 站着敲几下键盘/看看屏幕 → 退开 → 桌子整体推回边缘 → 隐藏并释放占位 → 恢复漫步。

先站着工作，省去椅子、坐姿和起身。真正坐下仍可做，但要增加腿部约 90° 旋转、可变化的身体高度和座位定位，不能只摆一张椅子。桌子、电脑、键盘可以用标准积木组合成一个道具根组，入口和退场通过根组移动完成，不必用刚体物理来“推”。工程难度中等。

“场外”应定义为底板边缘。现有镜头可以 360° 旋转，不能假定世界左侧永远在屏幕左边或看不见。道具待机时隐藏，开始后再从约定边缘进场；使用结束完整退出、隐藏，避免远处一直堆着备用道具。

这项最适合先验证：创建 → 入场 → 使用 → 退场 → 清理。两人共用一个短场景，在桌子撤走之前暂不恢复漫步，可先避免引入完整路径规划。

### 然后做种树

最小流程：选空地 → 手靠近腰侧 → 小种子/树苗在手部挂点出现 → 向空地伸手 → 道具从手部转交到地面 → 树苗立住或按积木增块长成小树 → 看看自己的成果 → 恢复。

现在没有可以真正打开的口袋，也无需制作布料模拟。用“靠近腰侧 + 被身体遮住时出现 + 抬手展示”的玩具表演即可实现掏出的感觉。种子变树是风格化的道具转换，不是实时植物生长模拟。若坚持零件尺寸一致，优先用树苗/树分阶段换模型或逐块出现，而不是把积木网格沿一个轴拉长。

手持 → 地面可以通过重新指定父节点完成。Three.js `attach` 会保留世界变换，但官方实现说明不支持含非均匀缩放节点的场景图，因此握持链与道具根组应保持统一缩放。[Object3D.attach 官方实现](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js#L794-L833)

种树的主要分界不是“从口袋掏出”难不难，而是树是否长期留下：

- 临时小树，用完收回：与桌子类似，难度中等。
- 种下后保留：增加场景对象登记、上限、合法栽种位置、圆形/矩形占位与漫步避障，难度中至高。首版可限定一棵纪念树，再次触发就是照顾同一棵树。
- 不先做无限种植、存档、浇水成长经济或动态破坏；这些是另一个产品范围。

## 动作增加前只需抽出的最小结构

1. **动作定义与运行实例分开。** 每个动作有进入、逐帧更新、完成与取消清理；运行实例保存本次双方站位、时间、效果是否已触发等，不靠全局 `hugHold` 承担所有动作。
2. **双人局部站位。** 围绕一个安全互动点安排两人的目标，按发型/持物包围范围留余量；不要所有动作都跳回世界中心。接近期间先接管两人移动，避免 wander 与剧本同时写位置。
3. **单一姿态写入顺序。** 基础站立/走路 → 当前动作 → 过渡回基础；头发和头部同步。新增根节点高度/倾斜时，调整每帧末的统一写回，避免坐姿和低头被下一段代码抹掉。
4. **短步骤队列。** 当前步骤完成才推进下一步；结束统一恢复姿态与漫步。组合按钮和单动作走同一执行入口，不需要增加 AI。
5. **道具管理单独一层。** 道具有唯一实例、所有者、场景/手部父节点、占位、显示状态和清理函数。重置、取消、失败都走同一清理路径；不能只 `visible=false` 却留下占位或活着的计时器。
6. **声音跟实际事件。** 亲到/击掌接触/树苗落地/桌子到位时发一次轻声，取消后不补发。沿用现有音乐与音效独立开关。

这是为扩充动作提炼必要接口，不建议在开工前建设完整游戏引擎、引入 ECS 或导航网格。Three.js 的 AnimationMixer/AnimationAction 支持关键帧动作与淡入淡出；以后复杂动作增多时可以选用，但眼下几段刚体姿态可以继续用现有帧时钟，避免两套系统同时驱动同一关节。[AnimationMixer 官方源码](https://github.com/mrdoob/three.js/blob/r180/src/animation/AnimationMixer.js)、[AnimationAction 混合/过渡官方实现](https://github.com/mrdoob/three.js/blob/r180/src/animation/AnimationAction.js#L304-L345)

Blender 官方源码将 Child Of 定义为可脱离父级约束，IK 定义为通过终点目标控制骨链；这些适用于以后在 Blender 制作更复杂的握持动作，不是当前网页必须采用的新依赖。当前 Empty/Group 关节与直接挂点已经足够做首轮。[Blender 约束类型官方定义](https://github.com/blender/blender/blob/main/source/blender/makesrna/intern/rna_constraint.cc#L103-L143)

## 每阶段应验收什么

Phase 1：远近不同初始位置都能完成；长发/眼镜/手持配件不明显穿插；头发不滞后于头；动作结束姿态正确；组合顺序一致；途中重新拼装不会残留音效/延迟回调；中英切换不重启动作；手机上仍能辨认姿态。

Phase 2：重复进出场不会新增重复道具；取消时角色、道具、占位都恢复；镜头环绕时道具不突然穿过角色或桌面；退出前角色先让开；有保留物时 wander 不穿树、不走进桌子；重新拼装能清空场景道具。

本报告的可行性结论来自源码和资产层级检查，并未制作这些动作，因此动作效果与穿插控制仍需实现后逐项验收。

## 第二轮已实施（2026-10-21）

`src/action-library.ts` 定义动作、双语文案、参与者、阶段、时长、站位与退出规则；`ActionScene` 逐段执行。新增牵手、击掌、招呼、并肩看风景、坐一会、等你一下，以及本轮要求的两条连续组合。随机小互动排除最近三项动作，随机组合排除最近两项，可以关闭自动互动。

`HandProps` 独立管理四件手持物：整段动作开始只放下一次；中间不拾放；完成或中断后先平滑恢复姿态，再返回释放位置依次拾取。全部拾回才恢复漫步。重新拼装立即清理模型、刚体和握持节点。

地面坐姿包括双腿约 90° 转动，身体高度由标准腿部实际顶点最低点计算；进入、退出和取消都保持桌面间隙。没有附带椅子，Phase 2 桌椅与种树仍未开始。
