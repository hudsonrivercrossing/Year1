# 照片人仔零件核对与还原顺序

基线：本地 Git `v1.0.0` / `7534e3f`。这轮只研究；没有替换网页模型或加入动作。参考原图：`assets/reference/anniversary-frame.png`。本地放大图仅用于辨识，不补造图像细节。

## 核对方法与置信度

对照照片放大细节、BrickLink 自有零件目录描述及目录原图，再在已下载的 LDraw 官方完整库 `/tmp/little-brick-ldraw.zip` 中核对文件头与映射关键词，并使用 LDraw 官网搜索作复核。BrickLink 编号、LDraw 文件名和 LEGO Element ID 不是同一套编号；编号不能直接互换。

“高”代表照片中可见的印花/外形与目录高度吻合，仍不代表识别了内部模具、背面或材质批次。“中”代表标准件候选，需要在实际 3D 角色中比对。单张照片无法确定某些软/硬材质版本、发型背部、身体背面印花与精确塑料颜色；暖光、玻璃反射和白平衡也会改变颜色。

手持配件既是照片识别特征，也会影响挥手、亲亲、拥抱时的碰撞间距。后续应明确：互动开始临时收起长杆/杯子/冰淇淋，结束再恢复，或设计持物专用姿势，不能让长杆穿过伙伴。这个挂点与收纳机制也可复用到 Phase 2。

## 真正落地时先改什么

1. 保留标准躯干、腿、肩和头部挂点。先替换 DJ 眼镜脸，补两件高置信度的躯干印花与准确底色。这样最直接提升“就是照片里的两个人”的辨识度。
2. 用候选发型做一个正面/侧面/背面对照；YW 优先看平刘海族，DJ 比较 99930 和 87991。内部模具或材质无法确定时，选择外形匹配且模型来源明确的版本，并写清近似项。
3. 添加可引用的手腕/持物挂点与配件显隐状态；不必改变首版每人 6 个可拼装组件的玩法。先补杖、杯、冰淇淋，再验证拥抱/亲亲的净空。
4. 参数配置拆出 `headPart`、`hairPart`、torso/arm/hips/legs 各自颜色和 prop 列表，避免目前腿髋同色、上衣手臂同色的耦合。

### 现有导入器的关键限制

`scripts/prepare_parts.py` 目前仅展开 LDraw 三角/四边形顶点并按色号分组，不读取 TEXMAP/UV。`src/main.ts` 的 `part()` 只特别识别色号 16、0、14，其它色号会退回角色主色；Blender 构建脚本有同样限制。因此，即使拿到彩色印花文件，直接替换 ID 仍可能丢掉白色/蓝色/肤色等印花。

落地前需补完整 LDraw 调色板映射。若官方/Tracker 找不到这两件同款印花，可在标准 973 几何上制作独立可替换的前后图案贴层，明确记录为“按标准印花参考重绘”的视觉版本。现有网格没有 UV，不能简单设置一张贴图就假设能正确显示；需明确投影贴层或 UV 方案。保留标准几何，不用整张目录照片当材质，也不把手绘近似登记为官方 LDraw 编号。

优先级：**两件上衣印花 + DJ 眼镜脸 → 发型 → 颜色分拆 → 手持配件与收纳 → 情感动作验收**。与动作路线的先后关系见 `docs/actions-roadmap.md`。
